# 几何后端接口与能力验证

AIDC 使用稳定设置名 `geometry.backend` 选择精确几何实现：

```text
geometry.backend = freecad-occ   # 默认生产后端
geometry.backend = usd-brep      # NVIDIA USD BRep 实验后端
```

后端选择与能力验证位于 `aidc_core.geometry`。接口只暴露后端描述、运行时探测和统一验证报告，不向上层泄漏 `TopoDS_Shape`、SMLib `Brep` 等原生对象。这样三维发布器、精确干涉服务和 MCP 后续可以在保持结果契约不变的情况下切换实现。

## 命令

查看已注册后端、状态和运行时位置：

```powershell
aidc geometry backends --json
```

验证实验后端并保存报告：

```powershell
aidc geometry validate --backend usd-brep --report geometry-validation.json --json
```

验证现有生产后端：

```powershell
aidc geometry validate --backend freecad-occ --report freecad-validation.json --json
```

统一报告采用 `aidc.geometry.validation/0.1`，包含运行时版本、耗时、逐项结果和数值指标。USD BRep 首轮验证覆盖基础实体、包围盒、体积、BRep 布尔求交、最小距离、网格化以及 OpenUSD BRep 导入导出。FreeCAD/OpenCascade 验证覆盖相同的核心计算能力。

USD BRep 1.0.0 的公开 Python API 可直接读取 OpenUSD BRep 和 SMLib 原生 `.smb`/`.smp`，没有提供 FCStd、STEP、IGES 或 JT 导入入口。因此能力基线可以通过，但 `productionQualification.ready` 必须保持 `false`。它暂时不能独立接管现有机器人 CAD 输入，后续需要验证可靠的精确格式转换路径或等待上游提供正式 CAD 导入 API。

## 运行时边界

`freecad-occ` 继续作为默认生产后端，并在隔离的 `FreeCADCmd` 进程中运行。`usd-brep` 使用锁定的 CPython 3.12 Windows wheel，当前标记为实验后端。开发环境可将 wheel 安装到 `.codex-runtime/usd-brep`；正式发行应将其放入受管 Python Runtime Pack 的 `Lib/site-packages`。

当前阶段只建立后端契约和能力基线，没有切换三维浏览器的生产精确校核服务。完成机器鸭、金刚十轴及异常 CAD 文件的对照验证后，再将精确校核服务接入该选择器。

本轮 Windows 实测结果保存在 [`distribution/audits/geometry-backend-validation.json`](../distribution/audits/geometry-backend-validation.json)。该审计只采用可重复构造的盒体基线，不能替代真实机器人 CAD 的生产准入测试。
