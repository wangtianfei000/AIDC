# 机器人全流程工具链：开源工具选型目录

调研日期：2026-09-17　｜　配套：[总体规划](机器人设计到制造全流程工具链_调研与总体规划.md)

本目录按业务类别整理候选方案，不是安装清单。“首选/按需/后置”是结合金刚现状的建议；仅核查官方仓库或文档，不代表已完成本地兼容性、性能或维护质量测试。主要许可证标签只描述上游主项目或声明，依赖、插件、模型与数据需分别记录；未明确的地方保留待核查。

集成优先采用文件、CLI、Python API 或服务 API，尽量让相同输入可以重放。工具应记录版本、输入输出哈希、日志、异常和超时行为。以下每个项目名称链接均为本轮核查的一手来源。

## 11. 建议的选型验证方法

不以 Stars 或是否“看起来功能齐全”作为最终标准。每个进入首期的候选工具，用同一个金刚样例完成以下工程验证，并记录结果：

| 维度 | 建议权重 | 核查方式 |
|---|---:|---|
| 核心任务覆盖 | 30% | 能否完成实际样例，并产生完整交付物 |
| 自动化与格式互通 | 25% | CLI/API 能否重复运行；输入输出是否可读可校验 |
| 现有资产与平台适配 | 20% | 对当前 FCStd、MJCF、ONNX 和运行环境的迁移成本 |
| 可维护与可复现性 | 15% | 版本锁定、安装重建、错误处理和升级回归 |
| 团队使用成本 | 10% | 操作复杂度、文档、部署与排障时间 |

许可证/资产来源满足项目用途、关键硬件支持和关键功能可用性应作为入围条件，不宜被综合分数抵消。以上权重是建议值，尚未给候选工具打实测分数。

首轮 PoC 建议顺序：

1. FreeCAD 修改参数并导出，核对尺寸、件数、质量与来源。
2. 根据同一修订构建 MJCF，运行金刚 CPU 场景并检查协议。
3. 将一个 KiCad/成品模块接口样例与 WireViz 线束关联到 BOM。
4. 生成切片试制包，保存设备、材料和数量，验证一次首件。
5. 在 InvenTree 建立样机 BOM 和建造记录，完成一台机器实装追溯。
6. 从台架测试报告反查固件、策略、零位和物料；模拟一次设计变更并确认旧证据失效范围。

只有 PoC 通过后，再固定版本、写适配器契约和工程使用说明。当前目录是覆盖全流程的候选地图，首期无需把全部工具装齐。
