# 系统架构、总体布局与装配方案论证：阶段分析

## 1. 结论

需求阶段之后应进入 **系统架构、总体布局与装配方案论证**。这一阶段要回答两个连续的问题：

> 已经知道机器人“要做到什么”，先选择“用什么整机方案做到”，再证明这些部件能够在真实空间中组成一台可运动、可装配、可拆修的机器人。

此时不应直接细化全部零件、定最终 PCB 或编写完整控制软件。应先确定机器人由哪些子系统构成、各子系统如何协作、关键指标怎样分配，以及质量、功耗、续航、成本和控制周期能否闭合。随后还要建立初步机械装配布局，确认关节轴线、真实部件包络、安装接口、承力关系、运动空间和装拆路径。

只有部件清单和逻辑连接的架构不能直接放行机械详细设计，因为它没有回答“这些部件如何装到一起”。本阶段的结果应同时包含系统架构基线和初步装配基线，作为机械、电气、控制和软件后续设计的共同输入。

## 2. 本阶段在机器人设计中的作用

需求文件描述的是业务目标，例如：

- 机器人应能遥控行走；
- 电池续航不少于 `2 [h]`；
- 有效负载不少于 `2 [kg]`；
- 接到停止命令后应在 `500 [ms]` 内停止运动。

系统架构阶段需要把这些目标转成整机方案。例如，“续航不少于 2 小时”会驱动电池容量、平均功耗、峰值电流、执行器效率、计算平台功耗和质量预算；“500 ms 内停止”会驱动通信周期、控制周期、执行器响应、安全状态和掉线处理。

因此，本阶段不是重复需求，而是逐步把业务目标落实为可装配的系统方案：

```mermaid
flowchart LR
    R[需求与验收基线] --> F[功能与工况分解]
    F --> C[候选整机方案]
    C --> T[方案比较与关键验证]
    T --> A[系统架构]
    A --> I[接口与参数分析]
    I --> L[运动骨架与总体布局]
    L --> P[初步装配与集成验证]
    P --> D[机械、电气、控制详细设计]
```

### 2.1 工程实践给出的修正

工程项目通常不会从系统框图直接跳到详细零件设计，而是在初步设计评审前逐步提高方案分辨率：

- NASA 的设计方案定义流程要求方案逐级细化到足以验证可实现性、成本和风险，并明确提醒方案比较要考虑线缆和维护人员如何维修；技术数据包也会从概念模型逐步演进为完整图样和零件表。[NASA Design Solution Definition](https://www.nasa.gov/reference/4-4-design-solution-definition/)
- NASA 的接口管理过程把物理、机械和电气接口纳入同一管理过程，并要求识别待装配的下层产品、完整配置、零件表和装配说明。[NASA Interface Management](https://www.nasa.gov/reference/6-3-interface-management/)
- NASA 对集成计划的定义包含系统元素的组合配置和装配顺序；机械接口控制内容会进一步描述紧固方式、孔位等可执行信息。[NASA NPR 7120.5F Appendix A](https://nodis3.gsfc.nasa.gov/displayDir.cfm?Internal_ID=N_PR_7120_005F_&page_name=AppendixA)
- SEBoK 将系统详细设计定义为架构和实现之间的桥梁，要求补充形状、尺寸、体积、受力和物理接口等设计特征，使系统元素具备实现条件。[SEBoK System Detailed Design Definition](https://sebokwiki.org/wiki/System_Detailed_Design_Definition)

这说明需要在系统架构后增加 **总体布局与初步装配设计**。它可以作为本阶段后半段，也可以在项目管理中单列为“初步机械设计”；无论如何，都必须在机械详细设计之前完成。

对当前工具链，建议把它们合并成一个面向业务的“总体方案设计”大阶段，但设置两个内部检查点：先通过 **架构方案检查**，再开展总体布局；完成 **初步设计评审** 后才允许进入零件详细设计。这样既保留系统架构和机械工作的职责边界，也不会产生“架构画完即可详细设计”的错误理解。

## 3. 本阶段必须回答的问题

### 3.1 机器人边界

- 哪些部件属于机器人本体，哪些属于遥控端、充电设备或外部计算设备？
- 机器人脱离网络后需要保留哪些能力？
- 本次设计针对哪个明确配置，是否包含不同尺寸、负载或传感器变体？

### 3.2 功能如何分配

- 行走、转向、停止、自检、姿态感知、电源管理和通信分别由哪个子系统承担？
- 哪些功能由机构自然实现，哪些由电子硬件实现，哪些由控制软件实现？
- 正常启动、运行、低电量、通信丢失和故障时，系统应进入什么状态？

### 3.3 整机方案如何选择

- 采用什么运动形式、关节拓扑和自由度？
- 使用什么类型和数量的执行器？
- 主控、实时控制器、传感器和通信链路如何组合？
- 电池、电压等级、稳压和配电方式如何选择？
- 控制算法运行在机器人本体还是外部计算设备？

至少形成两个可比较的候选方案。比较时围绕已经批准的需求，不以“功能更多”代替方案适用性。

### 3.4 接口是否清楚

对重要接口至少说明：

- 连接的两端；
- 传递的是机械载荷、电能、数据还是控制命令；
- 方向、单位、范围和更新频率；
- 启动、停止、超时和故障时的行为。

接口在此阶段定义到足以支持专业分工和初步装配。关键机械接口需要有坐标系、安装基准、轴线、孔位或安装面、载荷方向和空间包络；普通零件的完整公差和制造尺寸仍留到详细设计。

### 3.5 核心参数能否计算闭合

至少建立以下核心参数分析：

| 分析 | 本阶段需要确认的内容 |
|---|---|
| 质量 | 从部件质量和数量计算整机质量、上限和余量 |
| 功率、能量与续航 | 从电池可用能量和各子系统功耗计算平均功率、峰值供电、续航和余量 |
| 计算与通信 | 从采样、传输、计算和执行延迟计算控制周期占用与端到端延迟 |
| 成本 | 目标成本、主要子系统估算和风险项；数据成熟后再进入可执行计算 |
| 空间与热 | 关键安装空间和热源；需要几何或热求解器的部分在后续工具中完成 |

参数输入和结果必须带单位。公式、实际参数绑定和约束应记录在 SysML 中，结果由计算内核生成，不手工重复填写“当前估算值”。无法确认的输入应标为待验证项，并使相关结果显示“无法计算”，不能把缺值按零处理。

### 3.6 部件能否真实装配

初步装配不是把方框换成三维外形，而是确认以下问题：

- **装配层级**：整机如何分成躯干、腿、头部、电源和控制等模块，哪些零件固定，哪些部件随关节运动；
- **运动骨架**：关节轴线、方向、零位、限位、轴间距离和父子关系是否明确；
- **真实包络**：舵机、电池、主控板、传感器、连接器和线缆弯曲空间是否有可信尺寸来源；
- **机械接口**：驱动端和支承端、安装面、基准、孔位、紧固方式以及轴承或轮毂方案是否可行；
- **承力路径**：足端载荷如何经过关节、支架和机架传到躯干，外壳是否被错误地当成主要承力件；
- **运动与间隙**：典型姿态和关节范围内是否存在碰撞，线缆是否会被拉扯、夹伤或过度弯折；
- **装拆路径**：部件能否按合理顺序装入，工具能否接近紧固件，电池和易损部件能否独立更换；
- **装配后基准**：关节零位、IMU 方位、左右对称和脚底基准如何建立并检查。

这一层只需要证明结构方案可实现，不要求把所有支架、壳体、孔位、公差和工艺细化到可制造状态。

## 4. 建议的业务工作流

### A0：确认输入基线

读取需求文件，确认目标机器人配置、关键定量指标、使用环境和验收方法。将仍会改变架构的缺口列为待决问题，例如运动地面、最大坡度、目标成本或允许的整机质量尚未确定。

输出：可用于方案设计的需求基线和架构待决问题。

### A1：分解任务、功能和工况

从典型任务出发，分解机器人完成任务所需的系统功能，并补充启动、停机、低电量、通信中断和关键部件故障等工况。

输出：功能分解、运行状态和关键数据流。

### A2：提出候选整机方案

针对关节与机构、执行器、主控、实时控制、传感器、供电和通信形成两到三个自洽组合。候选方案必须是完整组合，避免只比较单个器件。

输出：候选架构及其主要假设。

### A3：比较方案并开展最小验证

依据关键需求比较各方案。对于无法通过资料或计算确认的高风险问题，开展最小可行验证，例如：

- 多执行器同时动作时的峰值电流和电压跌落；
- 给定电池质量下，是否能达到 `2 [h]` 续航；
- 执行器总线能否满足目标控制周期；
- 主控能否在周期内完成感知、控制和通信；
- IMU 坐标、更新率和通信协议是否可用。

输出：方案比较结果、实测或计算证据、选型理由和遗留风险。

### A4：建立系统架构、接口和参数分析

确定系统及子系统层级，为部件定义职责、端口和连接，同时使用 `calc def`、分析调用和约束建立质量、能量/续航、峰值供电和控制时序计算。把顶层需求分配到负责的子系统；暂时无法分配的需求作为显式遗留项处理。

输出：选定架构、接口定义、可追溯的参数计算链、约束结论和需求责任分配。

### A5：建立运动骨架和总体布局

先建立参数化运动骨架，再导入或绘制可信的关键采购件包络。按装配层级布置执行器、电池、主控、传感器和线束空间，并同步检查质量、重心、外廓和散热条件。

这一阶段的 CAD 是“布局装配”，不是制造 CAD。允许自研结构件保持简化，但采购件的外形、输出轴、安装面、连接器和必要拆出空间不能继续用无依据的方块代替。

输出：关节和坐标基准、初步三维装配、部件布置、质量与重心估计、运动包络和干涉清单。

### A6：论证装配、拆卸和集成顺序

从单关节或单腿开始，说明各模块如何装配，再说明模块如何组成整机。对关键连接确定驱动端、支承端、紧固方向和工具空间；对电池、控制板、传感器等维护件验证拆出路径；对线束确定主路径、活动余量和固定点。

优先用一个关键模块的样件验证最不确定的接口，例如舵机安装与双侧支承、轴承配合、电池装入、板卡固定或跨关节走线。

输出：初步装配树、装拆顺序、关键机械接口控制信息、维护路径和接口样件验证记录。

### A7：初步设计评审与基线化

由机械、电气、控制、软件、制造和测试共同评审。评审重点是方案是否自洽、实物是否放得下和装得上、关键风险是否有证据、后续专业能否据此开始工作，而不是评审图是否足够复杂。

输出：系统架构基线、初步装配基线、被否决方案及理由，以及允许进入详细设计的结论。

## 5. 建议交付物

本阶段不能只交付一个部件架构文件。建议用两个相互对应的核心模型表达不同信息。

`architecture.sysml` 作为系统语义事实源，内容保持精简：

- `part def` / `part`：机器人、子系统和关键设备；
- `port def` / `port`：机械、电源、控制和数据接口；
- `connect`：子系统之间的连接；
- 带单位的原始参数，以及质量、续航、峰值供电和时序所需的 `calc def`、分析调用与约束；
- 简短注释：部件职责、候选方案结论和关键假设。

初步 CAD 装配作为空间和装配事实源，至少包含：

- 与 SysML 一致的模块和部件层级；
- 关节轴线、坐标系、零位和限位；
- 关键采购件的可信三维包络和安装接口；
- 自研结构的骨架、安装面和空间预留；
- 电池、板卡、传感器、连接器和线束空间；
- 典型姿态、运动包络、干涉与拆出路径；
- 质量、质心和主要承力方向的初步结果。

SysML 负责说明“是什么、承担什么功能、通过什么接口连接”；CAD 负责说明“位于哪里、如何运动、如何安装和拆卸”。两者使用相同的稳定部件 ID 对应，不能把几何装配关系强行压缩成纯文本属性，也不能让 CAD 文件成为系统职责和需求关联的唯一来源。

需求仍保存在 `requirements.sysml`。架构模型通过稳定需求 ID 表达责任关联。当前 Parser 对跨文件引用和 `satisfy` / `allocate` 的支持还不完整，第一版可以在架构元素中使用简洁的需求 ID 引用；待 Parser 能力补齐后再转换为正式关系。

方案比较和验证证据可以先作为评审材料存在，不必把全部过程字段固化进 SysML 模型。架构文件保存最终选定方案及仍然有效的假设。

## 6. 金刚项目的首个试点

金刚现有资料中同时存在不同的执行器数量、计算平台、控制板、IMU、通信方式和供电假设。这正适合作为系统架构阶段的试点。建议先固定一个目标配置，再完成以下工作：

1. 明确该配置的运动任务、自由度和关节映射；
2. 将现有硬件组合整理成两个完整候选基线；
3. 比较执行器数量、控制链路、IMU、计算平台和电源方案；
4. 计算质量、平均功耗、峰值功率、续航和控制周期；
5. 对电源峰值、总线周期、IMU 数据和计算负载开展最小验证；
6. 建立关节轴线和主要尺寸参数的运动骨架；
7. 使用可信的舵机、电池、主控、IMU 和连接器包络完成初步装配布局；
8. 检查典型姿态干涉、承力路径、线束空间、电池与板卡拆出路径；
9. 形成可以交给机械、电气和控制详细设计的架构模型与初步 CAD 装配。

试点的第一目标不是做出最完整的机器人，而是消除现有资料之间互相冲突的系统级假设。

## 7. 软件和 AI 在本阶段的边界

延续需求阶段的原则：**AI 创建和修改 SysML 文本，软件负责浏览。**

AI 技能应指导如何读取需求、生成候选架构、建立参数计算、记录假设并形成 `architecture.sysml`。浏览器复用现有模型导航和属性查看能力，并逐步增加真正有业务价值的架构视图：

- 系统组成树；
- 部件连接图；
- 核心参数分析概览；
- 参数表和计算依赖图；
- 计算公式、实际参数绑定、目标、余量和诊断详情；
- 需求到子系统的责任视图。

不再新增独立的部件表和接口表，也不以固定字段“预算表”替代计算。部件与接口信息继续通过模型导航、架构图、属性查看和源码定位浏览；参数分析由 Runtime 根据 SysML 中的计算定义求值。装配交接表只是已有信息的汇总，本轮后移。

浏览器不承担方案自动决策，也不需要内置复杂编辑器。当前已有 Part、Port 和 Connection 浏览能力；下一步先补 Calculation/Analysis 的 Parser 语义、单位感知计算内核和只读参数分析视图。详细规划见[《SysML 参数计算与分析：实施规划》](SysML参数计算与分析_实施规划.md)。

三维装配需要 CAD 工具承担。SysML 浏览器后续只需为架构部件提供关联 CAD 对象或文件的入口，并显示布局检查结果摘要，不应自行发展为机械 CAD 编辑器。

## 8. 阶段完成门槛

满足以下条件后，才能进入机械详细设计以及并行的电气、控制详细设计：

- 已选择一个明确的整机架构，被否决方案及原因可查；
- 每项顶层需求都有负责子系统，或被明确列为待决问题；
- 机器人组成、职责、端口和关键连接清楚；
- 质量、续航、峰值供电和控制时序具有可执行、可追溯的计算链，并保留合理余量；
- 关键接口的方向、单位、范围、频率和故障行为足以支持专业分工；
- 影响架构的高风险问题已经有计算、资料或最小验证证据；
- 关节轴线、方向、零位、限位、轴间距离和部件随动关系明确；
- 关键采购件采用可信包络和安装接口完成了初步三维布置；
- 典型姿态与运动范围的干涉、线束空间、质量、质心和外廓已经检查；
- 关键机械接口说明安装基准、驱动与支承关系、紧固方向和载荷路径；
- 已形成从模块到整机的初步装配顺序，关键维护件具有可行拆出路径；
- 至少一个高风险安装接口通过样件、实物或等效几何验证；
- 机械、电气、控制和软件团队无需自行发明系统级决定即可开始后续设计。

## 9. 建议的下一步

先执行参数分析 C0：针对金刚明确配置建立质量、续航、峰值供电和控制时序四条最小计算链。每条链都要明确原始输入所属部件、数值来源、单位、公式、目标约束和手算结果，并把将被计算输出替代的手工估算字段列出。

随后按 C1—C4 依次补齐 Calculation Parser、单位感知计算内核、金刚计算样例和浏览视图。完成核心参数闭环后，再继续初步 CAD 装配和装配交接表。实施顺序见[《机器人系统架构与总体布局：实施计划》](系统架构与总体布局_实施计划.md)和[《SysML 参数计算与分析：实施规划》](SysML参数计算与分析_实施规划.md)。
