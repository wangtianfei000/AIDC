# AIDC 机器人装配发布包规范 1.0

状态：规范基线。清单版本：`aidc.robot.assembly/1.0`。

## 1. 目的

三维模型转 Modelica 的输入是机器人装配发布包，不是单个 STL。STL 只描述一组三角面，不能表达零件归属、刚体树、关节、质量属性、执行器、传感器或控制接口。本规范规定 CAD/三维装配完成后交付给 Model3D Viewer、Robot IR、Modelica 和 MuJoCo 的公共目录、身份和引用关系。

包根目录中的 `assembly.manifest.json` 是唯一入口。消费者不得根据文件名猜测结构，也不得通过网格相邻关系猜测关节。

## 2. 交付边界

正式装配包只有一种状态：可生成并仿真的完整交付物。CAD 解析结果、整机预览 GLB、碰撞预览、运动学抽取结果、命名姿态、推荐仿真设置、来源明细和校验报告均属于发布过程的中间文件，不进入正式包。缺少质量、惯量、关节、设备或接口时，发布器应报告缺项并停止生成装配包。

### 2.1 常见三维工具原生导出能力

| 导出物 | 装配层级 | 刚体/关节语义 | 质量与惯量 | 适合用途 | 结论 |
|---|---:|---:|---:|---|---|
| 原生 CAD（如 FCStd） | 有 | 取决于装配/关节工作台 | 通常可计算 | 权威编辑源 | 不能作为跨工具运行时格式 |
| STEP AP242 装配 | 有 | 通常只有产品结构和变换 | 材料与质量属性支持不一致 | 中性 CAD 交换 | 可作为发布器输入，仍需语义配置 |
| 单个 GLB/glTF | 有节点层级 | 没有统一机器人关节契约 | 通常没有 | 浏览和可视化 | 作为整机可视资产，不作为唯一事实源 |
| 一组 STL/OBJ | 没有可靠装配关系 | 没有 | 没有材料时无法确定 | 逐体运行时网格 | 必须由清单绑定到刚体，不能直接当装配体 |
| URDF | 有连杆树 | 有基础关节/惯量/传动 | 可有 | 机器人交换 | 可导入 Robot IR，但表达能力和单位仍需校验 |
| AIDC 装配发布包 | 有 | 有，并以稳定 ID 跨文件引用 | 必须有 | 浏览、Modelica、MuJoCo | 本工具的产品输入 |

因此发布器不是简单选择一种 CAD 导出格式。它读取原生 CAD 或 STEP 装配，在工作目录中完成抽取和校验，最终只发布 Robot IR 与实际引用的逐刚体网格。

## 3. 标准目录

```text
<robot>.aidc-assembly/
├─ assembly.manifest.json             # 唯一入口、模型身份、来源和全部文件摘要
├─ physics.json                       # 刚体树、关节、质量、惯量、接触、姿态和几何引用
├─ devices.json                       # 执行器、电源和传感器
├─ interfaces.json                    # 命令、状态和诊断接口
├─ geometry/
│  ├─ <body-id>.stl                   # physics.json 实际引用的逐刚体可视网格
│  └─ <body-id>-collision.stl         # 仅在使用网格接触时存在
```

若模型只使用解析几何且不需要外部可视网格，`geometry/` 可以省略。浏览器依据 `physics.json` 中的刚体树和局部变换装配逐刚体网格，因此不再重复保存整机 `visual.glb`、`collision.glb` 或 `kinematics.json`。源 `FCStd`、STEP、JT 和发布报告由工程源库或构建缓存管理，不复制到运行包。

## 4. 清单契约

可执行 JSON Schema 位于 `packages/assembly-package/schemas/assembly-manifest.schema.json`。清单至少包含：

- `packageId`、`modelId`、`revision` 和 `name`；三份 Robot IR 必须具有相同模型身份。
- `source` 只记录源格式、发布器版本以及可选的源 URI/摘要，代替独立 provenance 文件。
- `files` 记录除清单自身外每个交付文件的相对路径、字节数和 SHA-256。
- `physics.json` 是结构事实源，统一保存坐标约定、刚体、关节、质量属性、命名姿态、接触和几何引用，不再在清单或 `kinematics.json` 中重复。

同一个机械实体在 CAD、GLB 节点、运动学、Robot IR、Modelica 和 MuJoCo 中必须沿用同一 `bodyId`/`jointId`。显示名称可以变化，稳定 ID 不得由文件名或数组下标生成。

## 5. 装配导出要求

### 5.1 三维/CAD 发布器负责

1. 保留产品装配层级和零件实例，不把整机无条件熔合成一个网格。
2. 按运动学连接关系划分刚体；同一刚体可包含多个零件实例。
3. 导出局部坐标中的逐刚体运行时网格；浏览器和仿真器依据 `physics.json` 组装整机。
4. 碰撞可复用可视网格、使用单独简化网格或使用解析形状，但只发布实际引用的资源。
5. 提供关节原点、轴、类型、父子体和限位。CAD 中未定义的字段标记缺失，不能猜测。
6. 能从材料和实体求得时输出质量、质心和惯量，同时记录来源；薄壳、非封闭体或缺材料时不得静默用默认密度替代。
7. 对每个产物计算 SHA-256 和字节数，再写清单。

### 5.2 领域配置负责

CAD 通常不包含电机控制语义，因此执行器型号、减速器、电池、传感器、接触材料、接口通道和仿真初值由设备库、SysML 或人工配置补齐。三份 Robot IR 全部通过校验后才创建正式装配包。

### 5.3 生成器负责

生成器先校验清单、摘要、引用、树结构和 Robot IR，再生成 Modelica。它不得从三角网格推断关节，也不得为缺失质量属性填入看似有效的默认值。

## 6. 校验规则

`python packages/assembly-package/src/assembly_package_validator.py <目录>` 执行以下检查：

- Schema、相对路径和包边界安全；
- 文件存在、字节数和 SHA-256 一致；
- 清单必须登记包内全部文件，禁止多余中间文件；
- 三份 Robot IR 通过 Schema、稳定 ID、刚体树、惯量、设备和接口语义校验；
- `physics.json` 引用的每个几何都存在并登记，`geometry/` 不得包含未引用资源；
- 装配清单与 Robot IR 的模型身份一致。

Modelica 生成执行同等强度校验；不完整目录直接返回缺项诊断。

## 7. 当前发布物的迁移

当前 Model3D FreeCAD 发布器输出 `aidc.model3d.package/0.1`、`visual.glb`、`collision.glb` 和 `kinematics.json`。这些是现有浏览与发布流水线产物，不是新的最小装配包；它尚未输出逐刚体运行时网格和完整 Robot IR。

迁移顺序为：

1. FreeCAD 发布器按 `bodyId` 生成逐刚体网格；完整 GLB 和碰撞预览只留在构建缓存。
2. 从 CAD/材料库计算或录入质量属性，合并设备和接口配置，生成根目录三份 Robot IR。
3. 删除未被 `physics.json` 引用的几何，生成最终 `assembly.manifest.json`。
4. 通过装配包校验后，Modelica 与 MuJoCo 从同一最小包生成。

## 8. 单个 STL 的定位

Modelica Browser 仍保留“单零件 STL”入口，用于验证网格读取、单位、密度积分和单刚体显示。该入口产生的只是单刚体测试 Robot IR，不代表机器人装配转换流程，不能用于声明多刚体机器人已完成转换。
