# 机器人初步 CAD 装配设计

把已选系统架构转化为能够回答“零件是否放得下、装得上、动得了、拆得出”的三维工程模型。初步装配可以简化不影响这些判断的内部细节，但每个零件的关键外形、安装接口、轴线和维护空间必须正确或明确标为未确认。

开始建模前阅读[工作流程](references/workflow.md)和[几何与装配契约](references/modeling-contract.md)。建立三维浏览器可消费的工程、切换模型或交付发布包时，阅读[模型工程与发布包规范](references/model3d-project-contract.md)。需要把装配交给 Modelica 建模与仿真时，必须阅读并执行[Modelica 最小装配包导出规范](references/modelica-assembly-export.md)。准备检查和交付时阅读[验证与退出清单](references/verification-checklist.md)。遇到资料缺失、硬件配置冲突或已有模型只有包络时，按[异常场景](references/acceptance-scenarios.md)处理。

需要机器可读清单时，以[装配清单示例](assets/assembly-manifest.example.json)为结构起点，根据项目实际内容删减或扩展。

## 守住工程事实

- 先冻结本轮配置，再画装配。不得在同一装配中混用不同方案的主控、控制器、执行器、传感器或电池。
- 优先使用厂家 STEP、正式尺寸图、受控源 CAD 或实物测量。仓库已经存在详细几何时，不得重新用方盒覆盖。
- 区分厂家模型、受控设计几何、图纸重建、实测重建和规划包络。来源状态写入 CAD 属性和交付清单。
- 方盒、圆柱等包络只允许表示尚未选型或只需空间预留的对象；名称、颜色和状态必须显示“占位/待验证”，并阻断相关接口的完成判定。
- 不猜测孔位、花键、螺纹、轴端、连接器、出线方向、质量、材料或公差。缺失信息保留为阻断项。
- `componentId` 与 SysML、CAD、BOM 和验证记录保持一致；不得依靠易变的对象显示名称建立追溯。
- 物理装配层级是 CAD 模型事实。必须在 FreeCAD 的 `App::Part` 包含关系中定义，并在 FreeCAD 模型树中直接可见；发布配置和浏览器不得另建一套父子树。
- SysML 分解用于系统语义和追溯，不替代 CAD 物理包含关系。两者通过稳定 ID 关联，允许层级不同。
- 初步装配结论不等于制造放行。没有完成公差、材料、强度、工艺和实物试装时，模型保持 `NOT_RELEASED`。

## 建立模型

1. 读取架构、部件 ID、物理组成、固定或运动关系、关节顺序、轴线、零位、限位和已选硬件；把 SysML 分解与 CAD 物理包含关系分别记录。
2. 盘点现有 STEP、STL、原生 CAD、图纸、实测记录和旧装配；识别版本、单位、坐标系和配置冲突。
3. 建立来源矩阵。对每个零件记录型号或零件号、几何来源、尺寸状态、质量来源、验证状态和缺失资料。
4. 在 FreeCAD 中建立全局坐标系、装配基准和稳定的 `App::Part` 物理层级。每个装配节点设置稳定内部 ID、可读标签和唯一父装配；先放置采购件与关节轴，再设计承力和安装件。
5. 先完成一个高风险模块，例如髋部、单腿、踝脚或头颈，再复制或镜像已经验证的左右结构。
6. 采购件保留影响安装和干涉的真实形状：主体、法兰、孔位、轴端、连接器、线缆出口、散热件和必要禁布区。
7. 自制件建立实际轮廓、壁厚、孔、沉孔、定位、支承、圆角、工具空间和拆装路径；影响载荷或干涉的形状不能用外包围盒代替。
8. 建立关节局部坐标、运动父子关系、研究零位和限位。固定替代件必须是机械固定连接，不能把删除的执行器留在模型中假装锁定。
9. 布置电池、主控、运动控制器、传感器、连接器和线束，并建立维护方向、最小弯曲半径和活动余量。
10. 为零件补充质量、材料或密度来源。计算整机质量、质心和总体外廓时，不使用重复的装配聚合体或无限基准几何。

具体的几何层级、对象属性和 FreeCAD 建议见[几何与装配契约](references/modeling-contract.md)。

## 验证模型

- 校验 SysML/CAD 稳定 ID 的追踪关系；CAD 物理层级、运动父子关系和 SysML 分解分别校验，不要求三者形状相同。
- 校验 FreeCAD 模型树与发布后的浏览器物理树具有相同根节点、标签、父子关系和节点数量。
- 对采购件检查文件版本、单位、外廓、孔距、轴线和接口方向；对图纸重建件把已知尺寸与假设尺寸分别列出。
- 对自制件检查封闭实体、壁厚、孔与紧固结构、左右件、配合间隙和可制造方向。
- 运行中立、极限和典型工作姿态的连续或足够密集扫掠检查；区分设计接触、共享端点和非预期刚体穿透。
- 检查电池、板卡、维护件、紧固件和工具的进入及拆出路径。
- 检查线束路由、关节活动余量、防夹和连接器插拔空间。
- 输出质量、质心、总体外廓、干涉、间隙和未关闭项，并给出这些结果的来源与适用姿态。
- 重新打开保存后的 CAD，确认对象数量、层级、属性和几何没有丢失。

验证细目和退出判定见[验证与退出清单](references/verification-checklist.md)。

## 交付

产品自动化入口是 `aidc_model3d_publish`、`aidc_model3d_export_modelica` 和 `aidc_model3d_open`；无 MCP 的终端环境使用对应的 `aidc model3d ...` 命令。发布和导出属于长任务，取得 `taskId` 后查询 `aidc_task_status`，完成后从 `aidc_artifacts_list` 获取产物，不直接运行仓库内 Python 或 PowerShell 脚本。

默认交付以下可复核内容；项目不需要的项目可以省略：

- 面向后续设计修改时交付原生 CAD 装配文件；只交付浏览模型时不强制包含源 CAD；
- 浏览发布物以 `visual.glb` 为主，并附带模型清单、运动学定义和需要的简化碰撞资产；不得用 STL 代替有层级和材质的主显示模型；
- 关键视角预览，以及必要的剖视或局部接口图；
- 零件/几何来源清单，包含版本、单位、尺寸、数量和哈希；
- ID 映射、关节契约和装配层级；
- 干涉、运动、拆装、线束、质量和质心检查结果；
- 阻断项与下一步所需图纸、STEP、选型或实测任务；
- 可重复执行的构建、导出和验证脚本。

面向 Modelica 的交付使用 `<robot>.aidc-assembly/` 最小装配包。该包只保留 `assembly.manifest.json`、三份 Robot IR 和 `physics.json` 实际引用的运行时几何；GLB、预览图、报告和中间转换文件不进入此包。物理参数和设备接口必须来自已审核 Robot IR，导出器只做一致性校验与封装，不从 STL/GLB 猜测质量、惯量、关节或执行器。

不要把建模工程、浏览发布物和发布归档混放成一组无边界文件。浏览器消费 `visual.glb` 和配套 JSON 契约，不要求访问源 CAD；发布器写入 `generated/`，对外交付物写入 `release/`。浏览器“打开模型”所需文件组合、格式能力和目录示例见[模型工程与发布包规范](references/model3d-project-contract.md)。

只有真实或可追溯重建几何覆盖所有关键部件，高风险接口能够装配，典型运动和维护检查没有未解释问题，且所有占位体都已替换或明确接受为后续输入时，才可以判定初步装配退出。制造放行必须使用单独的详细设计和验证流程。
