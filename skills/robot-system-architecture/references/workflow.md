# 机器人系统架构业务流程

本流程用于新建架构或进行影响多个子系统的重构。局部字段修订可以直接完成，但仍要遵守事实来源、单位和稳定 ID 规则。

## 1. 建立设计输入

读取需求文件和用户提供的硬件、试验、CAD 或供应商资料，形成设计驱动因素清单：

| 类别 | 要提取的内容 |
|---|---|
| 任务与工况 | 机器人完成什么任务、持续多久、在什么环境和负载下工作 |
| 运动能力 | 形态、自由度、速度、工作空间、姿态和稳定性门槛 |
| 安全行为 | 停止、限位、失电、通信中断、过流和热保护要求 |
| 物理边界 | 质量、尺寸、包络、负载和维护空间 |
| 能源与热 | 续航、供电电压、电流、峰值功率、散热条件 |
| 控制与通信 | 控制周期、时延、同步、协议和故障状态 |
| 外部接口 | 电气、数据、机械安装、充电、工具和人机接口 |

每项设计输入保留需求 ID 或来源位置。需求没有给出答案时，把它登记为未知输入，不补造数值。

## 2. 明确边界和假设

写清目标配置、系统边界、由外部系统承担的职责、研究工况和当前不覆盖的变体。为每个非来源事实标注其状态：

- **厂家数据**：有可定位的正式资料；
- **实测值**：有样机、仪器、工况和记录；
- **计算值**：可追溯到输入和公式；
- **规划估计**：用于预算和布局，尚未实测；
- **方案假设**：为推进设计暂定，必须有验证任务；
- **待确认**：没有可靠值，模型中不写伪数值。

## 3. 比较完整候选方案

至少形成两个覆盖全系统的方案。使用同一组问题比较：

1. 能否满足每个关键需求及其工况；
2. 运动形式与自由度是否足够；
3. 执行器能力、安装和支承风险；
4. 控制器、计算平台和传感器的职责边界；
5. 平均与峰值供电、续航和热约束；
6. 总线带宽、实时性、故障隔离和安全状态；
7. 质量、质心、包络、线束、紧固和维护路径；
8. 已有证据、未知项和验证成本。

不要用无来源的精确评分制造客观性。选型结论应说明决定性需求、关键权衡、淘汰原因和使结论可能反转的未知项。

## 4. 建立选定架构

先建立顶层组成和职责，再细化关键设备、端口和连接。组成层级服务于装配与责任划分；接口表达真实的能量、数据、命令或机械关系。只有对方案决策或下游工作有用的属性才进入模型。

随后建立参数链：原始输入 → CalculationDefinition → 当前配置调用与绑定 → 输出 → 需求约束。优先覆盖决定方案可行性的少数核心计算，而非收集大量孤立字段。

## 5. 准备装配交接

对每个需要进入 CAD 的对象提供稳定 `componentId`、父装配、固定/运动关系和 `cadRef`。运动组件还要提供关节轴向、研究限位及待验证的安装接口。真实包络不存在时明确使用占位体，并创建获取尺寸图、STEP 或实测包络的任务。

## 6. 输出评审结果

交付内容包括：

- `architecture.sysml`；
- 候选方案与选型理由；
- 数据来源状态及待确认输入；
- 核心计算的结果、约束和余量；
- 装配交接范围；
- 未关闭风险和下一步验证任务。

有 CAD 工具且用户要求建立布局时，可以继续创建初步装配。没有 CAD 工具或缺少真实几何时，只输出明确的 CAD 工作项，不声称完成空间验证。
