# 异常场景处理与 P3 验收

以下场景用于检查技能是否诚实处理不完整或不一致的工程输入。

## 场景一：缺少硬件信息

**输入示例**：需求给出 2 小时续航和 800 g 质量上限，但没有电池容量、典型电流、电子件质量及舵机安装尺寸。

**正确处理**：

- 可以建立系统组成、职责、端口和候选方案；
- 不生成电池容量、续航结果、质量合计或安装孔位的虚假数值；
- 计算链保留缺失输入，结果标记为不可计算；
- 将电池选型、典型电流测试、部件称重和尺寸资料列为待验证任务；
- CAD 只使用明确标注的占位包络。

**拒绝条件**：使用行业常见值、样例值或零值填补未知输入，并把结果描述为满足需求。

## 场景二：方案约束冲突

**输入示例**：已知部件的规划质量下界超过整机质量上限，或两个已批准需求对同一接口给出不兼容电压。

**正确处理**：

- 显式列出冲突的需求、来源和受影响子系统；
- 候选方案分别说明减重、改变配置、修改部件或请求需求变更的代价；
- 在用户或需求负责人做出决策前，不任意选择一个门槛，也不改写需求；
- 当前计算结果如实显示未通过。

**拒绝条件**：静默放宽目标、删除冲突需求或通过调整无来源参数制造通过结果。

## 场景三：单位错误

**输入示例**：质量写为 `800`，控制周期写为 `5`，或把电流与功率直接比较。

**正确处理**：

- 要求确认物理量及单位；若上下文有明确、权威的单位来源，可修正为带单位表达式并注明来源；
- 无法确认时不猜测单位，保留为待确认输入；
- 拒绝量纲不兼容的公式和约束；
- 修正后重新运行解析与计算验证。

**拒绝条件**：依赖变量名猜单位、把裸数字直接写入物理量，或忽略量纲错误继续给出结果。

## 端到端验收

使用技能资产中的规范样例检查：

1. 单文件能够由 AIDC Parser 解析；
2. 系统组成、端口和连接可投影为架构图；
3. 四条核心计算链能生成单位一致的结果和约束状态；
4. 规划估计与方案假设保持明确说明；
5. `cadRef` 和稳定部件 ID 可作为后续 CAD 交接键；
6. 运行项目 `npm run verify:p2` 后 P2 浏览与计算基线仍然通过。
