# AIDC SysML 浏览器

面向机器人需求、架构与参数分析的只读 Web 浏览器。它读取一个 `.sysml` / `.kerml` 文本文件，通过本机无 Qt Parser Runtime 获得模型与分析快照，再将同一模型渲染为需求、架构、参数表、计算依赖、详情和源码视图。

软件不编辑或保存 SysML 文件。AI 或文本编辑器负责修改文本，Git 负责版本管理；浏览器只负责把文本模型转换成便于人阅读和检查的视图。

三维 CAD 浏览属于独立的“三维模型浏览器”软件，不在本应用中加载 Three.js、GLB、运动学、干涉或装配模拟功能。两个软件通过稳定工程 ID 和发布模型包契约关联，不共享界面或运行时。

## 运行

在本目录执行：

```powershell
./start-browser.ps1
```

然后打开终端显示的 `http://127.0.0.1:4173/`。脚本会启动随附的无 Qt Runtime；停止脚本时也会停止由脚本创建的 Runtime 进程。

首次开发构建：

```powershell
npm install
npm run test
npm run build
```

也可以分别启动后端和前端：

```powershell
../sysml-parser-runtime/run-runtime.ps1 -Port 47321
npm run dev
```

## P3 已实现能力

- 文件选择与拖放，支持 `.sysml`、`.kerml`。
- 按 Package 完整层级展开/折叠的需求表格、需求树、单跳追溯图、验证矩阵和只读源码。
- 多模型工作区：可一次选择或拖入多个 `.sysml` / `.kerml` 文件；模型树直接合并显示各模型的顶层 Package，不增加文件名节点。每个模型独立保留解析快照、当前视图、选择和前后导航历史，文件切换与关闭集中在顶部当前模型区域。
- 左侧模型树和右侧属性栏支持拖动分隔线调整宽度，也可聚焦分隔线后使用方向键微调；宽度保存在浏览器本机配置中。空状态只保留文件选择和拖入入口。
- ID、正文、类型、状态、专业、变体和覆盖状态筛选。
- 统一元素选择、右侧详情、关系查看和源码行定位。
- 结构化解析诊断、Runtime/Parser 版本展示、刷新和失败时保留旧快照。
- Parser 不支持的能力以“暂不支持”显示，不把缺失数据解释成业务事实。
- 通用 `ModelSnapshot`、`ModelQuery` 和视图分层，可继续增加架构模型插件。

## P4 架构扩展

- Part、Port、Interface、Connector 的结构树和数量摘要。
- 可选择结构上下文的只读架构图，显示组成部件、边界端口和 Connection。
- Runtime 0.2.0 将 ConnectStatement 转换为通用 Connection 关系。
- `*.view.tsx` 自动发现机制；增加新模型视图无需修改应用外壳。
- 可从欢迎页打开 `robot-architecture.sysml` 示例。

## 模型驱动导航界面（0.3.0）

- 页面采用左侧模型导航、中央视图工作区、右侧属性查看器三栏布局，不再使用独立的全局视图菜单。
- 属性查看器固定在右侧；选择模型节点后立即显示属性、关系、需求业务字段和源码位置。
- 模型节点根据元素类型显示主视图打开按钮：需求进入需求视图，Part 进入架构图，Port/Interface/Connector 进入架构树。
- 节点的更多按钮或右键菜单列出该节点适用的全部视图，并可直接切换到属性查看。
- 模型树支持逐级展开和名称、类型、限定名搜索。
- Runtime 按 SysML 源码的 Package 作用域恢复导航层级；例如 `SimpleVehicleModel > Definitions > PortDefinitions`，不会再把嵌套包平铺为根节点。
- 默认需求示例使用参考项目的 `VehicleMode.sysml`；需求定义可在属性查看器中查看约束表达式和 `RequirementConstraint` 关系。
- 需求表格按 Package 所属层级分组，并按 `ID、名称、描述、属性、约束` 展示；Package 行可展开/折叠，筛选结果保留完整祖先路径。描述严格来自 `doc`，属性和约束按多行文本显示，ID 优先使用 SysML 短名（如 `<'1'>`）。

## DiagramProjection（0.4.0）

- 架构图通过 `DiagramProjection` 从 ModelSnapshot 生成 `DiagramModel 0.1`，图形组件不再从源码文本猜测结构。
- 支持 owned 组成图和 connected 子系统网络图。
- typed part 的类型定义端口按具体实例投影，图形端口 ID 同时包含实例 ID 和定义端口 ID。
- Connection 连接实例边界端口，端口不再作为画布上的独立节点。
- 金刚整机、左腿和供电网络三张契约图均有自动化测试。
- 0.4.0 使用临时确定性网格；0.5.0 已由下述 ELK 布局替换。

## ELK 自动布局（0.5.0）

- 使用 `elkjs 0.12.0` 的 Layered 算法为 DiagramModel 计算节点 bounds、端口位置和连接折点。
- 支持层次节点、固定顺序的边界端口和正交路由。
- 支持从左到右、从上到下和重新布局。
- 固定模型顺序和随机种子，相同输入重复布局结果一致。
- 架构图直接渲染 ELK 结果，连线不再由 SVG 组件自行计算。
- ELK 采用动态导入，仅在打开架构图时加载独立布局代码块。

## 参考图形元数据兼容（0.6.0）

- 从 Runtime 的 GraphicMetadata Annotation 读取部件坐标和尺寸、端口局部位置与边、连接标签与路由。
- 完整元数据直接复现；部分元数据固定已有节点并由 ELK 补齐；非法字段显示诊断并回退。
- 参考项目的 `left/right/top/bottom` 映射为 DiagramModel 的标准端口边。
- 架构图显示当前使用“参考图形元数据”“元数据 + ELK”或“ELK 自动布局”。
- 内置架构示例带最小 GraphicMetadata，可直接验证只读渲染。

## 参数分析浏览（0.7.0）

- 消费 Runtime `/analyze` 的 `AnalysisSnapshot 0.1`，浏览器不重复实现计算公式。
- 按 SysML `ViewUsage.expose` 生成表格行；按 `asElementTable.columnView` 生成列及顺序，并读取列内 `label : String` 作为表头。前端不维护表头名称字典。
- 支持搜索、状态筛选、逐列升降排序，以及通过/未通过/计算异常状态样式。
- 表格行联动模型树、右侧属性查看、计算详情、输入参数和源码定位。
- 计算依赖图从选定结果追溯直接与间接输入，可在图、表和源码间前进后退。
- 内置架构示例使用金刚核心参数模型，显示质量、续航、峰值电功率和停止响应四项分析。

## 计算语义依赖图（0.8.0）

- 使用 Runtime 输出的稳定绑定显示“实际输入参数 → CalculationDefinition → CalculationUsage → 分析输出 → Constraint”。
- 绑定边显示形式参数名称，避免按同名参数猜测实际参数。
- 约束同时显示目标参数、比较方向、目标值和通过状态。
- 点击输入、定义、输出或约束节点可同步模型导航与右侧属性查看。
- 依赖图支持 40%–250% 缩放、恢复 100%、适应窗口，以及 `Ctrl + 滚轮` 缩放；放大后通过画布滚动查看完整计算链。
- 多输入计算按上下顺序分配独立入边端口，绑定标签靠近各自输入；CalculationDefinition 使用独立上方泳道，避免输入绑定线穿过定义节点。
- `CALC DEF` 节点按公式内容自动调整尺寸并限制最大宽度，在依赖图中直接展示 CalculationDefinition 的局部量和返回值表达式；超长语句优先在运算符边界换行，完整保留内容且只在语句末尾显示分号。

## 计算详情（0.9.0）

- 详情区显示计算定义、分析中的计算调用、分析输出和关联约束，四类对象均可定位属性或源码。
- 以表格逐项显示形式参数到实际参数的稳定绑定，以及实际参数在模型中声明的值和单位。
- 区分输入、局部量和返回值，展示类型及表达式；浏览器不重复执行公式。
- 约束结论用中文说明实际值是否满足比较条件，并显示目标、余量和相关计算诊断。
- 属性查看过滤 `direction = 0`、默认 `is* = false` 和空值等 Parser 默认字段，业务值和非默认标志继续显示。

## 异常状态浏览验收（0.8.2）

- 参数表以中文显示缺少输入、单位错误、不支持、循环依赖和计算错误，异常值、单位、目标和余量统一显示“—”。
- 异常摘要统计各类中断，同时保留同一 Analysis 中已正常计算的结果，避免单项失败遮蔽其他结果。
- 计算详情明确显示中断状态、Runtime 原始原因和关联诊断；诊断可直接定位对应 SysML 源码行。
- 依赖图为异常节点增加中断标记，并显示与当前计算链相关的诊断，不把声明表达式误报为计算结果。
- 欢迎页“计算异常示例”可加载包含五类异常和一个正常结果的最小验收模型。

## P2 集成回归与样例同步（0.8.3）

- `samples/jingang-10axis-system-design/architecture.sysml` 是正式金刚架构样例的唯一源；VehicleMode 和计算异常样例也使用同一同步清单。
- `npm run samples:sync` 更新浏览器发布副本，`npm run samples:check` 校验 SHA-256；生产构建会先执行哈希检查，副本分叉时直接失败。
- 导航历史抽离为可测试状态模型，覆盖参数表、计算依赖图、源码之间的前进/后退和选中结果恢复。
- `npm run verify:p2` 一次完成独立 Runtime 0.9.x 健康检查、正式模型真值、输入变更重算、VehicleMode 回归、浏览器测试、样例哈希和生产构建。
- 门禁运行后生成 `results/p2-r4-integration-verification.json`，保存本次版本、哈希、真值和回归结果。

## 当前边界

- 独立 Parser 尚不支持 `verify`、`derive`、`refine`，`satisfy` 也未形成可用于业务验收的完整关系集。
- 当前 SourceSpan 覆盖元素声明区间，复杂匿名语法仍采用保守定位。
- `VehicleMode.sysml` 当前形成 559 个元素、15 条需求、297 条关系和 7 条约束关系，解析诊断为 0；高级声明仍只保证只读结构投影。
- Package 和普通元素层级均由仓库内解析器的源码作用域恢复；严重语法恢复区域仍可能出现归属偏差。
- Runtime 已不包含外部参考 Parser 代码；公开发行仍需确定 AIDC 仓库许可证并完成二进制签名。

默认示例位于 `public/samples/VehicleMode.sysml`，机器可读验证结果位于 `results/vehicle-mode-verification.json`。
